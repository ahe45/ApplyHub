# 데이터 처리 개선 적용 기록

적용일: 2026-09-19

## 적용 내용

| 분석 항목 | 적용 결과 |
|---|---|
| 수험번호 선형 검색 | 번호 형식별 DB 카운터, 트랜잭션 잠금, 수험번호 UNIQUE 제약, 충돌/교착 제한 재시도. 기존 번호는 그룹 최초 사용 시 MAX 조회로 기준을 잡는다. |
| DB 연결 재요청 | 접수·사진 저장의 설정 조회와 초기 스키마 작업을 같은 연결로 처리. 복원은 연결 반환 후 후속 작업 수행. 연결 1개 환경 검증. |
| 초기 전체 데이터 중복 조회 | 화면별 bootstrap은 전체 접수/답변/수험생/출력 이력 제외. 기존 전체 bootstrap 호출은 요청 내 접수 결과를 재사용한다. |
| 목록·대시보드 | 접수/수험표/출력 이력/서류 목록을 SQL 검색·정렬·페이지 조회로 처리. 페이지당 20건 기본, 최대 200건. 대시보드는 서버 집계, 상세 답변은 상세 조회 시 로드. 서류 미제출은 해당 전형의 서류 양식을 기준으로 계산한다. |
| 첨부 조회 중복 | 이미 조회한 접수 레코드를 사진·파일 읽기에 재사용. 수험표는 40명씩 읽어 렌더링. |
| 파일 생성 메모리 | XLSX는 100~200건씩 읽어 스트리밍 작성, 사진·PDF ZIP은 임시 파일로 작성. 백업도 DB 100행 단위와 파일 스트림으로 ZIP 생성. 완료 PDF 작업은 Buffer 대신 파일 경로 보관. |
| 가입 첨부 | 신규 업로드와 기존 base64 가입 파일을 파일 저장소로 분리. 회원 JSON에는 메타데이터, 세션에는 공개 메타데이터만 포함. 가입 실패 시 생성 파일 회수. |
| 반복 쓰기·잠금 | 답변/출력 이력/서류 상태/복원 쓰기를 행수·바이트 제한 일괄 쿼리로 처리. 서류 상태는 변경할 질문 행만 잠금. 문서 답변은 요청에 포함된 항목만 갱신. |
| 동기 해싱 | 관리자·접수 비밀번호 해시와 검증을 비동기 scrypt로 전환. 저장 형식은 유지. |
| 큰 요청·내보내기 | 접수 내보내기는 ID, 출력 이력 내보내기는 필터를 전송. 서버에서 원본 데이터를 다시 읽는다. JSON 30MiB, 바이너리 256MiB 제한. |
| 파일 저장 정합성 | 파일을 임시 경로에 작성 후 교체하고 DB 커밋. 일반 저장/커밋 실패는 원본 파일 복구. DB 연결 반환 후 이전 파일 정리. |
| 반복 마이그레이션 | 접수 사진·레거시 파일 답변 마이그레이션을 100행씩 처리. 정상 위치에 이미 저장된 사진은 재작성하지 않는다. |

## 작업 자원 제한

- 접수 엑셀/사진 내보내기: 동시 2개, 요청당 최대 50,000개 ID.
- 수험표: 동시 배치 2개, 계정별 배치 1개, 한 번에 2,000명, PDF 변환 브라우저 최대 2개.
- 수험표 결과 파일: 512MiB 제한, 보관 결과 합계 2GiB 도달 시 신규 작업 차단, 주기적 만료 정리.
- 백업: 동시 생성 1개, DB 일관된 스냅샷 사용. 예전 ZIP 복원 및 수정 호환성 검증.

## 검증

모든 DB 통합 테스트는 별도 임시 데이터베이스와 임시 파일 저장소를 생성해 수행했다. 운영 DB의 데이터 변경과 배포는 수행하지 않았다.

통과한 검증:

- 신규 데이터 처리 회귀 검증: 45건 페이지 분할, 중복 없는 페이지, 검색/상태 필터/정렬/선택지, 답변 없는 목록 및 bootstrap, 출력 이력 페이지, 엑셀 답변/출력 횟수, 12개 동시 번호 발급, 기존 번호 10,000개에서 다음 번호를 SQL 5회로 발급, 파일 저장/실패 복구, 가입 파일 저장/마이그레이션/세션 응답, 요청 크기 제한, 관리자 목록 3개 브라우저 화면.
- 동일 회귀 검증 및 초기화·접수·서류 저장을 DB 연결 1개로 재검증.
- 스키마 마이그레이션/기존 백업 복원, 관리자 권한/설정, 인증 메일, 템플릿 태그, 접수 소유권과 기간 검증.
- 서류 상태/페이지/권한/교체 업로드/백업 복원.
- 첨부 ZIP 동시 작업/권한/폴더/실제 바이트/만료 및 브라우저 다운로드.
- 단일·배치 PDF/ZIP, 출력 이력, 대시보드 집계/필터/화면 크기/상세보기, 수험표 편집기.
- 현행 질문 양식 생성/복사/삭제, 일정별 양식 적용, 서류 제출 및 이전 백업의 기본 양식 호환성.
- 변경·신규 JavaScript 57개 구문 검사 및 diff 공백 검사.

전체 npm test 실행은 기존 document-settings 브라우저 테스트의 옛 화면 선택자에서 중단된다. 현재 양식 선택 갤러리를 거치지 않고 data-applicant-field-select로 바로 질문을 선택하는 코드가 원인이다. 해당 테스트를 삭제하거나 검증을 생략하지 않았다. 현행 양식 화면은 별도 form-templates 및 document-status 테스트로 검증했다. 테스트 브라우저는 설치된 Chrome을 EDGE_PATH로 지정했다.

## 호환성과 남은 제약

- 기존 DB·백업 형식을 유지하기 위해 app_subm의 중복된 접수 공통 컬럼을 제거하거나 별도 요약 테이블로 강제 이관하지 않았다. 목록의 DB 집계·관련 값 조회 비용은 남아 있으므로 운영 데이터 규모에서 실행 계획을 측정한 뒤 요약 테이블 여부를 판단해야 한다.
- 전체 선택 유지를 위해 필터에 맞는 ID/수험번호 목록은 전송한다. 답변 전체 전송은 제거했지만 ID 목록 크기는 대상 수에 비례한다.
- 통합 PDF는 최종 문서를 병합하는 단계의 메모리 사용이 남는다. ZIP은 청크 단위로 파일 작성된다.
- 기존 서비스의 Buffer 반환 함수와 전체 bootstrap은 호환 호출을 위해 남겨 두었다. 실제 관리자 화면과 신규 파일 다운로드는 경량/파일 기반 경로를 사용한다.
- 백업 복원 입력은 256MiB 제한 안에서 메모리 파싱한다. 업로드는 base64 JSON 호환 형식을 유지하며 multipart/객체 저장소 전환은 포함하지 않았다.
- 파일 교체와 DB 커밋은 일반 예외 발생 시 복구하지만 프로세스 강제 종료까지 하나의 원자적 트랜잭션으로 보장하지는 않는다. 백업의 파일 자산 또한 DB 스냅샷과 동일 시점의 파일시스템 스냅샷은 아니다.
- 기존 중복 수험번호가 있으면 UNIQUE 제약 마이그레이션은 데이터를 임의 삭제하지 않고 명시적 오류로 중단한다.
- 운영 데이터에서 실제 응답시간, 최대 동시 접수량, 최고 메모리 사용량은 측정하지 않았다.
