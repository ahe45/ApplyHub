# Template Editor Kit

`client/template-editor-kit` is the portable entry point for the template editor UI.
Use this kit when another project needs the same toolbar, data tags, editable canvas, table tools, image tools, and preview rendering without copying files one by one.

The bundled table tools include row/column editing, merge/split, cell shading, vertical alignment, and border controls for target, line style, width, and color. The kit also includes page properties for paper size, orientation, and margins.

## One-command install

From the target project's root directory, run one command:

```powershell
node "C:\Users\ahe45\WebstormProjects\AdmitCard\scripts\install-template-editor-kit.js"
```

By default this copies the full portable editor into:

```text
public/admit-card-template-editor
```

Use a custom destination when the host project serves static files from another directory:

```powershell
node "C:\Users\ahe45\WebstormProjects\AdmitCard\scripts\install-template-editor-kit.js" --target "public/vendor/admit-card-template-editor"
```

If the destination was previously generated by this installer and you want to replace it completely:

```powershell
node "C:\Users\ahe45\WebstormProjects\AdmitCard\scripts\install-template-editor-kit.js" --clean
```

Then load the generated runtime loader from the host page:

```html
<div id="editorRoot"></div>
<script src="/admit-card-template-editor/loader.js"></script>
<script>
  (async () => {
    const editor = await AdmitCardTemplateEditorKitLoader.createTemplateEditor({
      root: "#editorRoot",
      initialHtml: "<p>초기 양식</p>",
      tags: [
        { label: "이름", dataKey: "name" },
        { label: "수험번호", dataKey: "examineeNo" }
      ],
      previewData: {
        name: "홍길동",
        examineeNo: "A-000001"
      },
      onChange(html) {
        console.log(html);
      }
    });

    window.templateEditor = editor;
  })();
</script>
```

The installer also writes these helper files into the target directory:

- `example.html`: standalone browser load check.
- `server-examples/template-objects.express.js`: optional Express route for barcode/QR SVG preview objects.

Open `example.html` through the host project's static server to confirm the copied kit loads correctly.

## Asset Boundary

The installed `loader.js` is the preferred integration point. It loads the CSS and scripts listed in:

- `client/template-editor-kit/manifest.js`

The order of `requiredScripts` matters. The kit depends on the existing editor modules and then exposes:

```js
globalThis.AdmitCardTemplateEditorKit.createTemplateEditor(...)
```

If you want the current AdmitCard tag preset, keep the default `includePreset` behavior. Other projects can pass `includePreset: false` to the loader and provide their own `tags`.

```js
await AdmitCardTemplateEditorKitLoader.createTemplateEditor({
  includePreset: false,
  root: "#editorRoot",
  tags: [{ label: "이름", dataKey: "name" }]
});
```

`baseUrl` should point to the installed kit directory when `loader.js` is served from a different URL than the assets.

## Browser Usage

```html
<link rel="stylesheet" href="/styles/base.css" />
<link rel="stylesheet" href="/styles/features/templates.css" />
<link rel="stylesheet" href="/styles/features/template-editor.css" />
<link rel="stylesheet" href="/client/template-editor-kit/template-editor-kit.css" />

<div id="editorRoot"></div>
```

After loading the scripts from the manifest:

```js
const editor = AdmitCardTemplateEditorKit.createTemplateEditor({
  root: "#editorRoot",
  initialHtml: "<div class=\"template-doc\"><p>@{이름}</p></div>",
  tags: [
    { id: "name", label: "이름", dataKey: "name" },
    { id: "examNo", label: "수험번호", dataKey: "examineeNo" },
  ],
  previewData: {
    name: "홍길동",
    examineeNo: "123100001",
  },
  buildApiUrl: (path) => path,
  onChange: (html) => {
    console.log(html);
  },
});

editor.insertTag("이름");
const html = editor.getHtml();
const renderedHtml = editor.render({ name: "김지원", examineeNo: "20260001" });
```

Page settings are persisted on the `.template-doc` element as `data-template-page-*` attributes, so another project should keep the saved HTML intact instead of stripping those attributes.

## Creation Options

`createTemplateEditor(options)` accepts these host-facing options:

| Option | Required | Purpose |
| --- | --- | --- |
| `root` | Usually | Selector or element where the kit renders its default shell. |
| `toolbarHost` + `surface` | Alternative | Use these when the host already owns the layout and only wants to mount the controls/canvas. |
| `tagHost` | No | Element where data-tag buttons are rendered. |
| `pagePropertiesHost` | No | Element where paper size/orientation/margin controls are rendered. |
| `statusElement` | No | Element used for editor status/warning text. |
| `initialHtml` | No | Saved template HTML to restore. |
| `tags` | No | Host tag definitions. Use this instead of AdmitCard presets in other projects. |
| `previewData` | No | Static preview record used by `render()` and generated objects. |
| `getPreviewData()` | No | Dynamic preview record. Takes precedence over `previewData`. |
| `getPreviewDate()` | No | Returns the date string used by date tokens. |
| `onChange(html, editor)` | No | Called after editor content changes. Save `html` in the host project. |
| `buildApiUrl(path)` | No | Maps generated object API paths to the host API base. |
| `buildPhotoUrl(record, context)` | No | Resolves photo URLs during preview rendering. |
| `generatedObjectSourceKey` | No | Data key used for barcode/QR value. Defaults to `examineeNo`. |
| `getGeneratedObjectValue(record)` | No | Custom barcode/QR value resolver. |
| `idPrefix` | No | Prefix for generated toolbar element IDs. Useful when multiple editors exist on one page. |
| `state` | No | Advanced: pass a previously created editor/preview state object. |

Tag definitions are normalized from this shape:

```js
{
  id: "name",              // optional stable ID
  label: "이름",           // button label and editor token text
  dataKey: "name",         // value key used during render()
  legacyTags: ["성명"]     // optional old token names to resolve
}
```

## Runtime API

- `setHtml(html, options)`: Replace canvas HTML.
- `getHtml()`: Normalize and return editor HTML.
- `insertTag(tag)`: Insert a configured data tag.
- `insertHtml(html)`: Insert raw HTML at the saved selection.
- `insertImage(file)`: Insert an image file.
- `applyCommand(command, value)`: Run a toolbar command.
- `undo()` / `redo()`: Use the editor history.
- `render(data, html)`: Render data-tag output.
- `renderInto(target, data, html)`: Render into a preview target.
- `destroy()`: Remove listeners and active editor sessions.
- `sync()`: Force editor state synchronization and trigger `onChange` if content changed.
- `renderToolbar()`, `renderTagPanel()`, `renderPagePropertiesPanel()`: Re-render mounted controls.
- `state`: Exposes the editor state object for advanced host integrations.

`setHtml(html, { resetHistory, notify })` defaults to `{ resetHistory: true, notify: false }`.
Set `notify: true` only when the host wants the restore operation to call `onChange`.

## Saved HTML Contract

Save the exact HTML returned by `editor.getHtml()`. The host project should not sanitize away these editor-owned details:

- inline `style` attributes used for table sizing, borders, cell padding, fonts, and images
- `.template-doc` and `data-template-page-*` attributes used for paper settings
- `data-template-tag-value` token spans
- `data-template-object-type` and `data-template-object-source` for barcode/QR objects
- `colgroup`, `rowspan`, and `colspan` table structure

When the host reloads a template, pass the saved HTML back through `initialHtml` or `editor.setHtml(savedHtml)`.

## Generated Objects

Barcode and QR objects are rendered as images whose URL is built from:

```text
/api/template-objects/{barcode|qrcode}.svg?value=...
```

The host must provide a compatible endpoint or map the path with `buildApiUrl(path)`.
Photo rendering does not require an AdmitCard photo API if the preview record includes `photoUrl` or the host supplies `buildPhotoUrl(record)`.

For an Express host, the installer generates:

```text
public/admit-card-template-editor/server-examples/template-objects.express.js
```

Mount it like this after installing `bwip-js` and `qrcode` in the host project:

```js
const { createTemplateObjectRouter } = require("./public/admit-card-template-editor/server-examples/template-objects.express");

app.use(createTemplateObjectRouter());
```

## Project Boundary

The kit intentionally does not include AdmitCard-specific storage or workflow:

- template card list
- `/api/templates` save, update, delete, activate calls
- application modals
- examinee database queries
- project-specific page navigation
- generated barcode/QR HTTP endpoint implementation
- host authentication/authorization

Those should stay in the host project and call the kit API.

Minimum host responsibilities:

1. Serve the installed `public/admit-card-template-editor` directory as static files.
2. Mount the editor with `AdmitCardTemplateEditorKitLoader.createTemplateEditor(...)`.
3. Save `editor.getHtml()` or the `onChange` HTML into the host database.
4. Restore that HTML through `initialHtml` or `setHtml()`.
5. Provide preview data, photo URL resolution, and generated object endpoints when those features are used.
