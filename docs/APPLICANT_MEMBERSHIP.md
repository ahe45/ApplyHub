# 지원자 회원제

## 화면

- `/applicant-members`: 관리자·슈퍼관리자 전용 회원 목록. 접수하지 않은 회원도 포함하며 이름/이메일 검색, 접수 여부 필터와 20명 단위 페이지 이동을 지원한다. 가입 답변·첨부파일·약관 동의 상세에서 연결된 접수 상세를 열 수 있다. 비밀번호 해시·인증번호·로그인 토큰은 목록/상세 API에 반환하지 않는다.
- 데이터 삭제의 `회원가입 데이터`는 관리자 비밀번호 확인 후 회원 계정·답변·회원 첨부파일·약관 동의·인증/세션을 삭제한다. 기존 접수 이력은 보존하며 `app_meta.member_id` 연결만 해제한다. 접수 이력만 삭제할 때는 회원 계정을 유지한다.
- 회원 계정·답변·회원 첨부파일·약관 동의는 기존 데이터베이스 백업의 `applicant_members` 테이블에 함께 포함된다. 가입 양식은 `system_set`, 접수 연결은 `app_meta`로 함께 백업/복원된다. 복구 검증 화면에 현재/백업 회원 수를 표시하며, 로그인 세션·인증번호·비밀번호 재설정 토큰은 백업하지 않고 DB 복원 시 무효화한다.

사용자 입력 화면은 질문 제목 옆에 `필수`(빨간색)·`선택`(파란색) 배지를 표시한다. 회원가입·접수·서류 제출·비밀번호 재설정의 입력 오류와 인증/첨부 성공 안내는 해당 입력란 아래에 표시하며, 오류 안내를 읽는 보조기기와도 연결한다. 입력값은 오류 발생 시 유지한다. 접수 완료·일정 등 화면 전체 안내는 별도로 유지한다.

- `/login`: 수험생은 인증한 이메일, 관리자는 기존 ID를 사용하는 공통 로그인과 회원가입 링크. 관리 계정은 기존 권한별 관리 화면으로, 수험생 계정은 `/applicant`로 이동한다. 관리 계정의 초기 비밀번호 변경 절차는 유지한다.
- `/account-recovery?mode=password`: 이름과 가입 이메일을 확인하고 이메일 인증번호로 비밀번호를 재설정한다. 별도 ID 찾기 UI/API는 제거했고 기존 `?mode=id` 화면 링크는 비밀번호 재설정으로 전환한다. 관리자 계정에는 계정 관리 담당자 문의를 안내한다.
- `/applicant`: 로그인한 수험생의 원서접수·서류 제출·접수결과 조회·수험표 조회 순서의 2×2 메뉴. 비로그인 접근은 `/login`으로 이동한다.
  접수 전에는 원서접수만 사용할 수 있다(기존 접수 일정 조건 유지). 접수 완료 후 원서접수는 비활성 `접수완료`로 바뀌고 결과 조회는 상시 활성화한다. 수험표 조회·서류 제출은 본인의 모집시기·전형에 설정된 각 기간 안에서만 활성화하며, 미설정·기간 전·기간 후에는 비활성화한다.
  메뉴는 서버 기준의 시작·종료 시각을 사용하고 1초마다 기간 경계를 확인한다. 탭 복귀 및 홈에서 30초마다 접수 상태·일정을 다시 확인하며, 상태 조회 실패 시 동작을 차단한다. 실제 PDF/서류 요청에서도 서버가 기간과 소유권을 다시 검증한다.
- `/applicant/signup`: 약관 동의 → 정보 입력 순서로 회원가입한다. 관리자 설정에서 약관 사용이 꺼져 있으면 첫 단계에 별도 약관이 없음을 안내하고 다음으로 진행한다. 이전 버튼으로 돌아가도 입력값과 첨부파일은 유지한다. 이메일/PW/이름은 기본 필수이며 삭제·종류 변경·선택 항목 전환은 제한한다. 나머지 질문은 원서접수와 동일한 질문 카드·추가/수정 패널·선택지 편집·필수 설정·순서 이동/드래그·삭제·미리보기 UI로 관리한다. 질문은 기본 항목 포함 최대 50개. 제목·설명·정렬·답변 종류는 실제 회원가입 화면에 반영된다.
- `/applicant/documents`: 관리자의 서류제출 탭에 등록된 질문에 답변하고 파일을 제출·교체한다. 원서접수의 파일 질문은 표시하지 않는다. 해당 모집시기·전형의 별도 서류 제출 기간을 따르며, 접수 종료 후에도 서류 제출 기간이면 이용할 수 있다. 미설정·시작 전·종료 후에는 제출 및 교체를 차단한다.
- `/applicant-schedules`: 접수·서류 제출·수험표 조회 기간을 개별 또는 일괄 설정한다. 서류 제출 시작·종료를 모두 입력해야 하며 종료 분의 59초까지 허용한다. 기존 일정에는 빈 서류 제출 기간을 추가하고 다른 기간은 변경하지 않는다. 원서 작성 중 첨부는 기존 접수 기간을 그대로 따른다.
- `/applicant-question-template-management`: 가입·접수 설정 메뉴이며 `원서접수 / 서류제출 / 회원가입 / 약관관리` 순서의 4개 탭으로 구성한다. 서류제출 탭(`?tab=documents`)은 원서접수와 별도의 질문 추가·수정·삭제·순서 변경·미리보기를 제공한다. 회원가입 탭(`?tab=signup`)은 질문 항목을, 약관관리 탭(`?tab=terms`)은 약관 추가·수정·삭제·순서 이동을 제공한다. 약관은 질문과 동일한 카드 목록·오른쪽 편집 패널·선택 강조·이동/삭제 아이콘을 사용하며 드래그 순서 변경과 회원가입 화면 미리보기를 지원한다. 약관마다 제목·내용·필수 동의·사용 여부를 설정한다. 이메일 인증은 필수로 고정되며 회원가입 질문과 약관은 관리자·슈퍼관리자만 변경 가능하다. 기존 `/applicant-signup-settings` 주소는 회원가입 탭으로 이동하며 별도 메뉴는 제거했다. 설정 저장 API와 데이터는 그대로 유지한다.
- 공통 로그인과 지원자 하위 화면은 최대 520px의 세로형 모바일 레이아웃을 PC에서도 유지한다.
- `/login-notice`: 공통 로그인 공지(`login`)와 수험생 로그인 후 공지(`applicant`)를 구분해 편집한다. 저장된 사용자 공지는 그대로 보존하며, 이전 자동 생성 기본 로그인 안내만 공통 안내로 표시한다.

약관은 최대 20개이며 제목 100자·내용 30,000자까지 설정한다. 사용 중인 약관만 회원가입 첫 화면에 순서대로 표시하며 필수 약관은 모두 동의해야 하고 선택 약관은 미동의로도 가입할 수 있다. 기존 단일 약관은 제목·내용·사용 여부를 유지하여 필수 약관 한 개로 변환한다. 회원별 `consent_json`에 약관 식별자·제목·원문·필수 여부·동의 여부·동의 시각을 저장한다. 이후 설정 수정·삭제는 기존 회원 동의 기록을 변경하지 않는다. 사용 중인 약관 내용·순서·필수 여부 등이 변경되면 이전 화면에서의 동의로 가입할 수 없다.

기존 생년월일·연락처 및 추가 입력 항목 설정은 `questions` 목록으로 읽어 변환하며 기존 식별자와 회원 답변을 보존한다. 질문 삭제는 기존 회원의 답변을 지우지 않는다. 약관은 별도 탭에서 관리한다. `/applicant/signup?preview=1`에서는 실제 회원가입과 이메일 발송을 실행하지 않는다.

회원가입의 이메일·비밀번호·이름은 맨 위 1~3번에 고정한다. 이동 버튼과 드래그를 비활성화하며 일반 질문도 기본 항목 위로 이동할 수 없다. 서버는 설정 조회·저장 시 같은 순서를 적용하고, 기본 항목의 제목·설명과 일반 질문끼리의 순서는 유지한다.

회원가입 약관 제목 오른쪽의 전문보기 버튼은 해당 약관의 전체 내용을 모바일 크기의 팝업으로 표시한다. 긴 내용은 팝업 내부에서 스크롤하며 닫기·Esc·배경 클릭으로 닫을 수 있다. 열람 자체는 동의로 처리하지 않고 기존 체크 상태와 입력값을 유지한다.

회원가입 API는 계정 생성·인증번호 사용 처리·기존 접수 연결·로그인 세션 생성을 한 트랜잭션으로 완료한 후 HttpOnly 로그인 쿠키를 발급한다. 로그인 세션 생성에 실패하면 가입도 취소되어 같은 인증으로 재시도할 수 있다. 성공하면 기존 브라우저의 회원 세션과 관리자 세션을 해제하고 새 계정으로 `/applicant`의 2×2 메뉴로 이동한다. 별도 로그인 입력은 필요하지 않다.

원서접수 폼의 기본 정보에서 이메일 다음에 회원 생년월일을 읽기 전용으로 표시한다. 회원 정보의 기존 `birth` 또는 회원가입 양식의 생년월일 질문 답변을 사용하며 `yyyy년 mm월 dd일` 형식으로 월·일을 두 자리로 표시한다. 등록된 값이 없으면 `-`와 미등록 안내를 표시한다. 기존 원서 답변은 변경하지 않는다.

원서접수의 새 질문 종류에서는 생년월일을 제외한다(일반 날짜는 유지). 기존 생년월일 질문은 삭제하지 않고 회원정보 자동 연동 항목으로 안내한다. 회원 생년월일이 있으면 원서 화면의 중복 생년월일 입력란을 숨기고 상단 기본 정보만 표시하며, 접수 저장 시 서버가 회원정보의 값을 사용한다. 기존 회원에게 생년월일이 없으면 기존 원서 입력란을 유지한다. 기존 접수 기록은 일괄 변경하거나 삭제하지 않는다.

회원가입과 원서접수의 답변 종류·설명은 공통 정의를 사용하되 생년월일은 회원가입에만 제공한다. 공통 새 질문은 텍스트·전화번호·국적·선택지·날짜·사진 업로드·파일 업로드 중 선택한다. 이메일·비밀번호·이름은 선택 목록에 포함하지 않으며 회원가입 고정 항목 편집 시 종류 선택란 대신 고정 항목 안내를 표시한다. 실제 화면의 날짜/생년월일 선택과 국가 검색 결과도 공통 UI로 표시한다. 회원가입 날짜는 부분 입력·존재하지 않는 날짜·미래 생년월일을 차단하고 국적은 검색 결과에서 선택한 국가 코드를 기존 형식대로 저장한다. 전화번호는 숫자만 입력하며 최대 20자리이다. 기존 일반 질문과 답변, 업로드 파일은 유지한다.

회원가입 파일 답변은 원서 파일과 구분하여 회원 `profile_json`에 파일명, MIME, base64로 보관한다. 사진은 JPG/PNG, 서류는 기본 PDF/JPG/JPEG/PNG이며 파일 질문마다 허용 확장자를 변경할 수 있다. 파일당 5MB, 전체 8MB로 제한한다. PDF/이미지는 파일 시그니처도 검증하며 그 밖의 허용 파일은 일반 첨부로 저장한다. 질문 종류에 따른 필수값, 선택지, 국적, 날짜, 연락처 검증도 서버에서 수행한다.

파일 업로드 질문에는 `fileNamePattern`과 `allowedExtensions`가 있다. 원서 질문은 기존 `options_json`에, 회원가입 질문은 질문 설정에 저장하여 별도 DB 변경 없이 백업에 포함한다. 규칙은 고정 문구와 `{질문제목}`, `{원본파일명}`, 원서의 `{수험번호}` 또는 회원가입의 `{ID}`(인증한 이메일)를 조합한다. 확장자는 자동 부착한다. 원서 사용자 지정 이름에는 수험번호·질문 키에서 만든 16자리 식별자를 붙여 다른 업로드와의 충돌을 방지한다. 빈 규칙은 기존 원서의 수험번호_질문제목, 회원가입의 원본 파일명을 유지한다. 원서 확장자 설정이 비어 있으면 기존처럼 제한하지 않는다. 설정 변경은 새 업로드에 적용하며 기존 파일을 바꾸거나 삭제하지 않는다. 확장자는 대소문자를 구분하지 않고 화면과 서버에서 모두 검사하며 마지막 확장자를 기준으로 한다.

## 인증과 데이터

관리자 `accounts`와 별도의 `applicant_members`를 사용한다. 회원 비밀번호는 salt를 포함한 scrypt 해시로 저장한다. 세션 원문은 HttpOnly 쿠키에만 저장하고 DB에는 SHA-256 해시와 12시간 만료 시각을 저장한다. HTTPS 쿠키는 Secure 속성을 사용한다. 다중 프로세스에서 세션은 공유되지만 요청 빈도 제한은 프로세스별이다.

수험생은 이메일을 로그인 ID로 사용한다. 회원가입의 별도 ID 질문은 기존 설정을 읽을 때 제거하며 이메일 인증을 끌 수 없다. 신규 회원의 login_id와 email에는 인증한 이메일을 소문자·앞뒤 공백 제거로 정규화하여 저장한다. 기존 계정의 별도 login_id는 보존하지만 인증 조회는 email로만 수행하므로 이전 ID로 로그인할 수 없다. DB login_id는 이메일 길이를 지원하도록 255자로 확장한다. 기존 회원번호·비밀번호·접수 연결·파일은 변경하지 않는다. 이메일 미인증 계정과 기존 세션은 차단되며 비밀번호 재설정으로 이메일 소유를 확인하면 email_verified를 갱신하여 로그인할 수 있다. 이메일 변경 기능은 제공하지 않는다. 추가 시에는 새 이메일 재인증이 필요하다. 비밀번호는 가입·재설정 시 4~20자로 제한하고 기존 비밀번호로의 로그인은 유지한다. 관리자 계정 규칙은 별도로 유지한다.

공통 로그인 API는 `/api/auth/login`이다. 관리 계정 ID는 예약되어 있으며 해당 비밀번호 실패 시 수험생 계정으로 재시도하지 않는다. 수험생 가입 이메일과 관리자 계정 ID의 충돌을 양쪽 생성 경로에서 검사한다. 로그인 성공 시 반대 종류의 기존 세션을 해제하고, 공통 로그아웃은 두 세션을 모두 해제한다. 지원자 세션은 관리자 API 권한으로 사용하지 않는다.

회원가입 이메일 인증은 필수이며 기본적으로 실제 SMTP를 사용하며 인증번호를 API 응답에 포함하지 않는다. 관리자 시스템 설정의 이메일 발송 설정을 우선 사용하고, 미저장 시 `.env`의 SMTP 설정을 사용한다. 비밀번호는 암호화하여 보관하며 설정 조회·bootstrap 응답에 포함하지 않는다. 인증번호는 10분 유효, 최대 5회 검증, 동일 이메일 재발송은 10초 간격이다. 발송 실패 시 가입 인증을 우회하지 않는다.

개발 중에는 `NODE_ENV=development`와 `APPLICANT_SIGNUP_CODE_PREVIEW=true`를 함께 설정하면 회원가입 인증번호 발송 버튼 아래에 개발용 번호를 표시하고 SMTP 발송을 생략한다. 번호를 직접 입력해 인증을 완료해야 하며 유효시간·시도 제한은 그대로 적용한다. 인증 완료 또는 이메일 변경 시 표시를 지운다. 기본값은 꺼짐이며 `NODE_ENV=production`에서는 표시 플래그가 켜져 있어도 코드가 노출되지 않는다. 운영 배포 시 표시 플래그를 제거하거나 false로 바꾸고 NODE_ENV를 production으로 설정한다. 계정 찾기·비밀번호 재설정의 이메일 인증에는 적용하지 않는다.

비밀번호 재설정은 개발 모드에서도 실제 SMTP 인증을 사용한다. 계정 존재 여부는 인증 전 응답으로 노출하지 않도록 입력된 이메일에 동일한 인증 메일을 보내고, 이름·이메일이 일치할 때만 재설정을 허용한다. 복구 번호는 별도 applicant_member_recovery 테이블에 해시로 저장하며 10분 만료·5회 제한·일회 사용을 적용한다. 이전 ID 찾기 용도 번호는 사용할 수 없다. 비밀번호 변경, 이메일 인증 상태 갱신, 기존 세션·복구 요청 해제는 한 트랜잭션으로 처리한다. 복구 테이블은 백업에서 제외하고 전체 삭제·복원 시 비운다.

`app_meta.member_id`로 회원당 한 접수 건을 연결한다. 이메일 인증을 완료한 신규 가입자는 동일한 이름·이메일의 기존 미연결 접수 중 가장 최근 건을 연결한다. 이메일 인증 없이 신규 가입할 수 없다. 관리자 접수 이력 데이터는 삭제하지 않는다.

수험생 계정의 접수는 한 번만 저장할 수 있으며, 완료된 원서의 재접수·덮어쓰기 요청은 `409 APPLICANT_ALREADY_SUBMITTED`로 거부한다. 회원 행 잠금과 기존 접수 행 재확인으로 동시 요청·오래된 토큰도 차단한다. 접수 일정이 다시 열려도 완료 계정은 재접수할 수 없다. 관리자가 삭제하지 않은 기존 연결 접수도 완료 건으로 취급한다. 별도 서류 제출 기간의 첨부 제출·교체 기능은 유지한다.

접수/조회/PDF/서류 API는 회원 세션으로 본인 여부를 검증한다. 기존 이름·이메일·접수 비밀번호 기반 공개 인증 API는 로그인 안내와 함께 차단한다. 관리자 미리보기는 화면 테스트만 허용한다.

DB 전체 백업에는 회원 정보가 포함된다. 세션/이메일 인증 데이터는 백업하지 않으며 DB 복원 후 모두 만료시킨다. 전체 데이터 삭제에는 지원자 회원 및 세션 삭제가 포함된다. 정적 파일은 공개 자산 디렉터리에만 한정하며 설정·DB·백업·첨부 원본 경로의 직접 접근을 차단한다.

`node scripts/signup-question-test.js`는 기존 설정 변환, 기본 항목 보호, 답변 종류별 검증 및 파일 제한을 확인한다.

## 서류제출 질문 분리

`app_form.form_scope`로 원서접수(`application`)와 서류제출(`documents`) 질문을 구분한다. 기존 질문은 모두 원서접수로 유지하며 파일 질문과 답변을 이동하거나 삭제하지 않는다. 최초 서류제출 질문 목록은 비어 있다. 서류제출 탭의 새 질문은 파일 업로드로 고정하며 답변 데이터 종류 선택란과 종류 안내는 표시하지 않는다. 제목·설명·필수 여부·파일명 규칙·허용 확장자를 설정한다. 기존에 저장한 질문과 답변은 보존한다.

공개 양식 API는 `fields`(원서접수)와 `documentFields`(서류제출)를 분리해서 반환한다. 원서접수 시 서류제출 필수 질문은 검사하지 않고, 서류제출 저장 시에는 등록된 서류제출 질문만 허용한다. 서류제출 답변은 기존 접수 건에 저장하며 원서 답변과 첨부파일은 보존한다. 서류제출 화면 미리보기는 질문을 표시하고 입력할 수 있지만 실제 저장은 하지 않는다.
서류제출 파일은 기본 이름에도 질문별 식별자를 붙여 원서접수에 같은 제목의 파일 질문이 있어도 기존 파일을 덮어쓰지 않는다.

`npm run test:document-settings`는 임시 데이터베이스에서 기존 질문의 구분 전환, 원서·서류 질문 분리, 필수값 및 확장자 검증, 파일 보존, 관리자 질문 관리와 순서 변경, 수험생 답변 저장 및 미리보기의 저장 차단을 확인한다.
