# ApplyHub 원서접수시스템 — Quiet Glass UI

프로젝트 전체에 **콰이어트 글래스** 스타일을 사용하며 로그인·관리자 화면의 모드 버튼으로 라이트·다크를 전환한다.
첫 방문은 라이트 모드를 사용하고, 이후에는 브라우저에 저장한 선택을 사용한다. 공통 로그인, 회원가입/약관,
비밀번호 재설정, 접수 홈, 원서접수, 접수결과, 수험표 조회, 서류 제출은 물론
관리자 메뉴 전체, 표/필터, 편집 패널, 팝업, 공지 미리보기에도 동일한 소재와 색상을 적용한다.
원본 문서, 업로드 이미지, 사용자 지정 로고/공지 본문, PDF 출력은 UI 테마와 분리한다.

## 스타일 기준

가입접수설정은 원서접수·서류제출·회원가입·약관관리 탭 순서로 표시한다. 서류제출 탭에서 별도로 등록한 질문만 수험생 서류제출 화면에 표시하며 원서접수의 파일 질문은 포함하지 않는다.

- 공통 팔레트: `styles/quiet-glass-tokens.css` (`base.css`에서 불러옴)
- 공통 소재/컨트롤: `styles/quiet-glass.css`, 공개 화면 규격: `styles/features/public-glass.css`
- 각 기능 스타일의 기존 파랑/회색도 공통 변수로 교체했다. 새 스타일 추가 시 같은 변수를 사용한다.
- 이전 공개 화면 테마 파일과 클래스는 제거했다. 관리자 화면의 업무용 배치는 유지한다.
- 로그인·회원가입·비밀번호 재설정·수험생의 모든 화면은 최대 폭 520px, 최소 높이 `100dvh`의 공통 프레임을 사용한다. 바깥 여백 없이 모든 화면 크기에 같은 1px의 옅은 테두리를 적용한다. 모바일에서는 프레임이 화면 경계에 맞닿고, 데스크톱에서는 중앙 프레임의 테두리로 영역을 구분한다. 프레임 내부에는 최소 12px의 입력 안전 여백과 기기 안전 영역만 확보한다. 관리자 화면과 공지 편집 영역은 이 프레임 변경 대상에서 제외한다.
- 로그인은 내용이 실제 표시 높이를 넘을 때만 본문 영역을 스크롤한다. 하단 저작권 문구 위 여백은 12px이다.
- 관리자 페이지를 제외한 로그인·회원가입·비밀번호 재설정·접수 메뉴와 하위 페이지는 내용이 화면에 들어오면 세로 가운데에 배치한다. 화면 높이가 부족하면 상단 안전 여백부터 시작해 전체 내용을 스크롤할 수 있다. 공개 화면 헤더의 학교명은 20px로 표시하고 긴 이름은 한 줄 말줄임을 유지한다.
- 공개 화면의 `body`와 바깥 레이아웃 모두 `100dvh`를 기준으로 삼아 모바일 주소창 때문에 하단에 빈 스크롤 영역이 생기지 않게 한다. 수험생 홈의 빈 환영 영역은 렌더링하지 않고 저작권 문구 위 간격은 로그인과 같은 12px로 유지한다.
- 공개 화면 바깥 배경 `#181818`, 프레임 `#0f1f2e` 위 `#274b65`·`#293255` 방사형 그라데이션
- 카드 `#203446`, 입력란 `#0f1f2e`, 테두리 `#456477`, 본문 `#ebf6ff`, 보조 텍스트 `#b7cede`
- 주요 동작 `#346d8f → #25546f` 그라데이션, 보조 동작/Notice `#2c465e`, 링크 `#c7e8ff`
- 카드 그림자 `inset 0 1px 0 #58798f, 0 6px 16px #00000016`, 프레임 테두리 `#4d6779`
- 오류·완료·경고는 어두운 의미 색상 배경과 밝은 텍스트로 표시한다. 입력 포커스는 밝은 청색 윤곽을 사용한다.
- UI 글꼴 Noto Sans KR, 실제 문서 출력의 글꼴과 색상은 유지
- 카드 모서리 24px, 입력란/일반 버튼 12px, 주요 터치 영역 최소 48px
- 로그인 후 2×2 메뉴는 원서접수·서류 제출 / 접수결과 조회·수험표 조회 순서로 배치하고 원서접수만 주요 색상으로 강조한다.
- 로그인 제목 18px, 입력란 높이 48px, 메뉴 카드 최소 높이 144px
- 이메일 인증·원서접수·접수결과·수험표·서류제출 페이지의 본문 카드 테두리와 내부 20px 여백을 제거해 공통 프레임 안의 너비를 모두 사용한다. 입력란·공지·메뉴 버튼·팝업 등 기능별 요소의 테두리는 유지한다.
  본문 카드는 바깥으로 그려지는 포커스 테두리와 버튼 그림자를 자르지 않도록 `overflow: visible`을 사용한다. 공통 프레임의 안전 여백 안에서 표시하므로 화면 너비는 늘어나지 않는다.
  원서접수와 서류제출의 질문 사이에는 옅은 구분선과 위아래 20px 간격을 둔다. 제목·설명·입력란·첨부 안내·검증 메시지는 같은 질문 안에 유지하며, 첫 질문 위에는 구분선을 넣지 않는다.
  홈 이동은 패널 위 공통 학교 헤더의 왼쪽 아이콘 버튼에서 제공한다.
  이메일 인증 제목 아래 소개 문구와 두 입력 영역의 뒤로 버튼은 표시하지 않는다.
- 접수용 인증코드 발송 성공 후 10초 동안 재발송을 막고 버튼에 남은 초를 표시한다.
  같은 탭의 페이지 이동·새로고침에도 재발송 대기 시각을 유지하며, 발송 실패에는 새 대기 시간을 부과하지 않는다.
  숫자 6자리 입력 완료·유효 시간 내에만 인증 확인 버튼을 활성화한다. 서버의 코드 일치 검증은 별도로 유지한다.
- 장식용 영문 소제목, 환영/소개 문구와 대시보드의 큰 소개 영역은 사용하지 않는다.
  로그인은 시스템명·모드 버튼 다음에, 접수 홈은 학교 헤더 다음에 Notice와 기능 패널을 표시한다.
- 관리자 공지 미리보기, 회원가입, 원서접수, 결과 팝업도 같은 간소화 기준을 적용한다.
  메뉴·섹션 제목, 관리자 작성 공지, 입력 조건, 약관, 오류·상태 안내는 유지한다.
- 필수/선택 배지는 청회색 채움/윤곽으로 구분하고, 오류/성공 메시지와 삭제 동작은 의미 색상을 유지
- 입력란 아래 오류/성공 메시지, 약관 전문보기 유지
- 가입·접수 설정의 공통 질문카드는 제목·설명·배지를 별도 줄로 배치한다.
  설명의 입력 줄바꿈을 유지하고 긴 URL·공백 없는 문자열도 카드 안에서 줄바꿈한다.
  카드 공간이 좁으면 이동·삭제 버튼을 아래로 내려 텍스트와 겹치지 않게 한다.
  설명이 없거나 공백만 있으면 카드에만 “등록된 설명이 없습니다.”를 표시해 한 줄 설명 영역을 유지한다. 저장 데이터와 수험생용 질문에는 이 안내를 넣지 않는다.
- 공지는 두 줄 텍스트 미리보기로 표시하고 전체보기/접기로 원문을 열람한다. 관리자 공지 편집기는 펼쳐진 상태로 표시한다.
- 공지 본문 및 사용자 지정 로고는 유지한다. 저장된 배경 이미지 설정은 삭제하지 않고 화면은 선택한 모드의 배경으로 표시한다.
- 출력 수험표의 문서 템플릿 및 PDF 생성 로직은 변경하지 않는다. 문서 내부 표에도 다크 UI 색상이 침투하지 않도록 별도 밝은 팔레트를 적용한다.
- 수험표 조회 화면은 `ticket-pdf-viewer`에서 PDF.js의 legacy 빌드로 각 페이지를 그린다. 모바일 내장 PDF 뷰어에 의존하지 않으며 도구모음을 표시하지 않는다. 화면 폭에 맞춰 페이지 크기를 조절하고 문서 배경은 두 테마 모두 흰색으로 유지한다.
  수험번호 행 오른쪽의 다운로드 링크는 기존 토큰 검증을 거치는 PDF 주소에 `download=1`을 붙여 원본 파일을 첨부 다운로드한다. 미발급 상태에는 다운로드를 표시하지 않으며, 미리보기 실패 시 재시도와 다운로드를 안내한다.
- PDF.js는 축소 파일과 gzip 전송을 사용하고, 패키지 버전이 일치하는 URL은 브라우저에 장기 캐시한다. PDF.js 의존성을 올릴 때 `ticket-pdf-viewer.js`의 버전 쿼리도 함께 변경한다.
  PDF 요청과 뷰어 로딩을 동시에 진행하며, 즉시 다시 렌더링되는 화면은 진행 중인 PDF 요청을 공유한다. 미리보기 해상도는 화면 폭과 최대 2배 픽셀 비율에 맞추고 첫 페이지부터 표시한다. 원본 PDF는 수정하거나 영구 캐시하지 않는다.

## 라이트·다크 전환

- 위 색상 기준은 다크 팔레트이며, 라이트는 화이트 중심의 맑은 Quiet Glass 팔레트를 사용한다.
  배경·카드 `#ffffff`, 프레임 `#fafcff` 위 `#e6f1ff`·`#f1efff`의 은은한 그라데이션,
  입력란 `#f4f8ff`, 네이비 본문 `#172b4d`, 보조 텍스트 `#506581`, 테두리 `#d8e4f3`.
  주요 버튼은 `#2563eb → #1d4ed8`, 보조 버튼·Notice는 `#eaf2ff`로 대비를 준다.
  회청색 면적과 채도를 줄이고 강조 색상만 선명하게 하며, 추가 반짝임·투명 효과는 사용하지 않는다.
- 구조, 모서리, 여백은 두 모드에서 동일하다. 최근 생성한 중간 톤·투명 유리 샘플은 적용하지 않는다.
- 공통 초기화 `client/app/theme.js`를 세 HTML 진입점의 스타일시트보다 먼저 불러와 첫 표시부터 선택한 모드를 적용한다.
- `html[data-theme]`로 팔레트를 선택한다. 저장 키는 `applyhub.theme`이며 `light`/`dark`만 허용한다.
  OS 설정은 선택을 덮어쓰지 않는다. 같은 출처의 다른 탭에도 변경을 동기화한다.
- 저장소를 사용할 수 없어도 현재 페이지에서는 전환 가능하다. 저장되지 않았거나 값이 잘못되면 라이트를 사용한다.
- `applyhub-theme-toggle`은 현재 모드의 아이콘만 44×44px 버튼으로 표시하고, 접근성 이름과 툴팁으로 다음 동작을 안내한다.
  로그인 헤더 및 관리자 상단에 배치하며 최소 터치 크기는 44px이다. 공지 미리보기 안의 버튼은 비활성이다.
- 로그인 외 사용자 페이지는 공통 학교 헤더(왼쪽 홈 / 가운데 학교 로고·학교명 / 오른쪽 로그아웃)를 표시한다. 패널 내부의 중복 홈·로그아웃 버튼은 제거한다. 로그인 전에는 로그아웃을 숨기되 같은 너비를 확보해 가운데 정렬을 유지한다. 학교명이 길면 한 줄 말줄임을 적용한다.
- 학교 헤더에는 별도 모드 버튼을 추가하지 않으며, 로그인에서 저장한 모드와 다른 탭의 모드 변경은 그대로 적용된다.
- 모드 전환은 화면을 다시 렌더링하거나 새로고침하지 않으므로 작성 중인 폼 값과 로그인 상태를 유지한다.
- 문서 출력은 항상 별도 밝은 팔레트로 유지하고, 공지 편집기만 선택한 UI 모드를 따른다.

## 시스템명과 프로젝트명

- 관리자 **시스템설정**에서 학교명과 학교 로고를 변경하고 저장한다. 학교명은 최대 100자, 새 로고 파일은 PNG/JPG/WEBP·최대 2MB를 지원하며 미리보기와 기본 로고 복원을 제공한다.
- 기존 슈퍼관리자 학교 설정과 같은 저장 값을 사용한다. 학교 정보가 없으면 원서접수시스템과 기본 로고를 표시한다. 공개 학교 정보 API는 학교명·로고만 제공한다.
- 회원가입, 접수 메뉴와 하위 접수 화면, 계정 찾기 화면에 학교 헤더를 적용한다. 공통 로그인 화면도 설정된 학교 로고·학교명을 표시하며, 오른쪽에 아이콘형 테마 전환 버튼을 둔다. 긴 학교명은 한 줄 말줄임과 전체 이름 툴팁으로 표시한다.
- 회원가입의 약관·정보 입력 단계는 바깥 카드 테두리·배경·그림자·패딩 없이 표시한다. 단계 표시와 폼 사이 중첩 여백을 제거하되 개별 약관 구분과 입력란 간격은 유지한다.
- 로그인 폼과 비밀번호 재설정도 같은 무테두리·무그림자·무패딩 바깥 패널을 사용한다. 비밀번호 재설정의 빈 상태 메시지는 공간을 차지하지 않는다. 입력란·버튼·공지와 오류 안내는 기존 스타일을 유지한다.

사용자에게 표시되는 시스템명은 `원서접수시스템`이다.
메일의 기본 발신자명과 제목에도 적용하되 명시적인 SMTP 환경 설정값은 유지한다.
프로젝트명은 `ApplyHub`, npm 패키지명은 `apply-hub`이다. WebStorm 프로젝트명과 모듈명도 ApplyHub로 변경한다.
기존 작업 경로 및 데이터베이스, 쿠키/저장소 키와 `AdmitCard*` 내부 모듈 식별자는 호환성을 위해 유지한다.

## 확인

- `npm run test:ticket-pdf`: 실제 PDF 렌더링으로 모바일/PC·두 테마·다중 페이지·가로 회전·도구모음 부재·수험번호/다운로드 배치·원본 다운로드·실패 후 재시도·화면 이탈 시 정리·미발급 상태를 확인한다. 회원/접수 정보와 PDF 생성 데이터는 테스트 응답을 사용하고, PDF.js와 정적 파일 경로는 실행 중인 서버에서 읽는다. 실제 iOS/Android 기기 검증을 대체하지 않는다.
  `node scripts/ticket-pdf-viewer-test.js --benchmark`는 390px 화면, 4배 CPU 감속, 1MiB/s 전송량과 60ms 지연으로 첫 페이지 표시 시간을 측정한다. 생성 응답은 고정된 테스트 PDF이므로 실제 서버 PDF 생성 시간은 측정에 포함하지 않는다.

- `node scripts/public-unframed-auth-ui-test.js`: 모바일/PC·두 테마의 로그인/비밀번호 재설정 무테두리 레이아웃과 본인 확인·인증·완료 단계를 확인한다(인증 요청은 테스트 응답 사용).

- `node scripts/login-scroll-layout-test.js`: 로그인 화면의 두 테마·모바일/PC, 작은 높이와 화면 높이 변경, 불필요한 스크롤 부재 및 하단 문구 접근성을 확인한다.

- `node scripts/school-header-ui-test.js`: 320/390/1440px·두 테마에서 긴 학교명, 로고, 홈 이동, 로그인 상태별 로그아웃 표시와 성공·실패 처리를 확인한다. `npm test`에서 임시 DB로 학교명·로고 저장 및 공개 헤더 반영을 확인한다.

- 접수 페이지 모집 정보는 라벨 위/값 아래로 배치한다. 값은 한 줄(24px) 높이를 유지하며 가용 폭에 따라 16px에서 14px까지 0.5px 단위로 축소하고, 더 긴 값은 말줄임 처리한다. 전체 값은 원문과 title 속성에 보존하며 화면 폭/웹폰트 로딩/재렌더링 시 다시 측정한다.

- 접수 신청의 이전 버튼은 사용자 접수 메뉴(`/applicant`)로 돌아간다. 로그인 회원을 이메일 인증 화면으로 보내지 않으며, 다시 원서접수를 선택하면 회원 정보를 불러와 접수를 진행한다. 위 테스트에서 메뉴 복귀·재진입·이메일 기본값 유지를 함께 확인한다.
